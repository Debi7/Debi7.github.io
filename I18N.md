# The interface in two languages

Added 2026-10-12 at the owner's request, on the branch `refactor-app`. The interface of the site - the menu, the
buttons, the labels, the messages, the feedback form, the sign-in pages, the account page and the admin panel -
is in English and in Russian. English is the default; a visitor switches with the button beside the menu, and
the choice holds on every page until it is switched back. The owner first asked for Russian by default and
corrected it to English the same day; nothing but one setting and one CSS rule depends on which it is.

The content is not translated, by the owner's decision: the 24 articles, the 21 video descriptions, their titles,
tags and categories read the same in both languages. So do the site's name and the About page's text.

## 1. Why one page and no /en/ addresses

The colleague asked why the CRM project switches languages in a few lines and the club could not do the same.
The CRM is a single-page React app: it renders in the browser, and i18next swaps the words on screen. The club is
a set of HTML pages built in advance, and every click loads a new page. Swapping words by script after each load
would show the default language first on every page.

With the content untranslated, a second set of pages at `/en/...` would hold the same Russian articles under a
second address. A search engine reads that as duplicate content, and nobody gains anything. So the language is
the visitor's setting, kept in `localStorage` like the theme, and every page carries the interface in both
languages:

- The inline block in `Head.astro` reads the setting before the first paint. When it finds Russian, it puts the
  class `lang-ru` on `<html>`.
- `custom.css` hides the spans of the language not shown.
- A switch changes the class and a few attributes, with no reload and nothing flashing.

No new dependency was added.

## 2. Where things are

- `src/config.ts`, `site.i18n`: the languages, `defaultLanguage`, the storage key `kb-lang`, and the event
  `lang:change` sent after a switch.
- `src/config.ts`, `site.sections`: the names of the sections in both languages, for the menu, the search filters
  and the titles of the list pages.
- `src/i18n/lang.ts`:
  - the types: `Phrase` is a string in every language; `Words` is a `Phrase` or plain content;
  - `inLang()`;
  - `langAttrs()`, for attributes;
  - `format()`, which fills `{name}` placeholders in every language.
    It imports only the config, so browser scripts may use it.
- `src/i18n/strings.ts`, `ui`: every interface string of the public site, the theme's keys first and the site's
  own below. The texts the colleague wrote in Russian are the `ru` halves, and the English ones are new.
- `src/i18n/admin.ts`, `adminUi`: the admin panel's strings. It is a separate file so that the public pages'
  scripts do not carry them.
- `src/components/T.astro`: `<T s={ui.key} />` prints one span per language. A plain string goes through as it is.
- `src/components/LangToggle.astro`: the button beside the menu. It shows the language on screen (EN or RU), and
  its label says where a press leads.
- `src/scripts/lang.ts`, the browser half:
  - `currentLang()` and `phrase()`, for text that cannot hold a span;
  - `setPhrase()` and `phraseElement()`, for text a script builds;
  - `setLangAttr()`, for an attribute a script sets;
  - `localize()`, for a clone of a template;
  - `setLang()`;
  - `initLang()`, which `site.ts` calls on every page. It binds the button, applies the attributes, and follows a
    switch made in another tab or a page restored from the back-forward cache.
- `src/components/Head.astro`:
  - the language block before the first paint;
  - the page title in every language (`data-<language>-text` on the title element), which `lang.ts` copies into
    `document.title`.
- `src/styles/custom.css`: the two rules that hide the other language. They are written for the default; if it
  changes, swap `ru` and `en` there.

## 3. How to write interface text

- **In markup:** `<T s={ui.key} />`.
- **For a string that is content:** pass the string itself; `T` prints it unchanged.
- **For an attribute** (`aria-label`, `title`, `placeholder`, `alt`, or a `data-*` that a script reads):
  `{...langAttrs({ "aria-label": ui.key })}`. Use one call per element, with all of its attributes. The attribute
  carries the default language, and `data-<language>-<name>` carries each language.
- **In a browser script that builds text:** `setPhrase(element, ui.key)`.
- **In a browser script that sets an attribute:** `setLangAttr(element, "title", ui.key)`.
- **For text that cannot hold a span** (an `<option>`, `confirm()`): `phrase(ui.key)` at the moment of writing.
  Listen for `site.i18n.changeEvent` to write it again.
- **For a message with values:** `format(adminUi.key, { n: 3 })`, which returns a `Phrase`. A value may itself be
  a `Phrase`, such as a status name.
- **A new string** goes into `ui` (or `adminUi`) in both languages. The `Phrase` type makes a missing language a
  type error.

Never write a visible interface string as a literal in a component or a script. `<html lang>` stays `ru`, the
language of the content. The English spans and attributes carry `lang="en"`, so a screen reader reads them in
English.

## 4. Special cases

- **Clerk's forms** (sign-in, sign-up, the account card) take their language once, in `load()`. Clerk's
  "Localization prop" (Core 3) says so, and English is Clerk's own default. `src/scripts/auth.ts` passes the Russian
  strings only when the page is Russian. The three `/auth/` pages reload on a switch (`reloadOnLanguageChange()`).
- **The admin panel does not reload**, because an editor may have unsaved text in the form. Its scripts write every
  message with `setPhrase()`, so a switch shows them in the new language at once. The status lists on
  `/admin/users/` are rewritten after a switch, because an `<option>` holds text only (MDN, `<option>`). A
  `confirm()` dialog gets the language shown.
- **The search page:**
  - The index stores the section's key (`posts`, `video`) instead of its label, and so do the filters and the
    `?section=` parameter. An old link with `?section=Posts` no longer ticks the box.
  - The status templates are language-dependent attributes, which `search.ts` reads in the language shown.
  - A switch draws the status line and the results again.
- **Dates on list cards:** `formatMonthDay()` in `src/lib/date.ts` returns both forms, `Sep 07` and `07 сен`.
  Both month lists are hard-coded, so the output does not depend on the build machine's ICU.
- **The tag-page count** uses the Russian plural: 1 статья, 2 статьи, 5 статей (`ruPlural()` in `strings.ts`).
- **Feeds, `og:*` and the meta description:** a feed or a share card has one language, so these use the default
  language.
- **Left in Russian on purpose:**
  - the subject of the letter the sign-in page's help sends, because it is read by whoever receives it;
  - the " (копия)" mark of a copied post's title, because that is content.

## 5. What a visitor sees differently

- **By default:**
  - The parts that were Russian are now English: the feedback form, the sign-in pages and Clerk's forms, the
    account page, the paid lecture's box, the comments button, the admin panel and the button back to the top.
  - The theme's strings were English already and stay English: the menu, the pagination, "Read more" and the
    footer.
- **After switching to Russian:** everything above is Russian, the menu included (Главная, Статьи, Видео,
  Категории, Теги, Кабинет, О нас). The section names are in `site.sections`.
- **The About page:** its heading is the section's name in both languages. The front matter's English title,
  "About", is no longer printed; `about.md` is unchanged.
- **The header:** the bar has one more control. Between 640px and about 830px the site's name gives way earlier
  than before (at 700px it reads "Ra..."), measured in headless Edge. Below 640px the switch sits first among the
  icons. If that band matters, the switch could move into the drop-down panel at those widths; that is the owner's
  call.

  remain.
